代码同步接入

日常配置在「研发协作 → 代码同步」。当前模式只推送已有提交，保留原 SHA、作者和提交描述。工作区未暂存、已暂存及新文件仅提示，不自动提交；同步到同名远端分支，无固定备份分支前缀。

1. 本机授权

源码根目录、SSH 身份与固定 Agent 路径由管理员批准。私有策略文件 0600、目录 0700，令牌与密钥不入 Git。

python3 scripts/code-sync.py policy-example --state data/native-admin
python3 scripts/code-sync.py policy-import --state data/native-admin --file /absolute/private/policy.json
python3 scripts/code-sync.py bootstrap-workspace --state data/native-admin

bootstrap 只发现主仓库并创建关闭配置；默认每日 02:00、Asia/Shanghai。detached HEAD 需由项目选择分支后再开启。

2. GitHub 凭据与预览

保存有指定仓库写入权限的令牌，在来源配置中选择。令牌保存在本机私有文件，API 不回显。推送前检查所有待发送提交和元数据，包括中间提交；命中敏感信息、临时文件、无法检查的内容或超过范围均停止。仅删除后续版本中的敏感文件，无法清除先前提交。检查是启发式规则，仍需项目提交审查。

有凭据时预览核对完整待推送范围；无凭据时只检查本地当前提交，不能据此判断整个推送范围已通过。分叉或来源 HEAD 变化时停止，不强推。

3. 目标设备

支持 Linux/macOS，需 Python 3.9+、Git 与同版本 Agent。Windows Agent 尚未支持。生成 schema 2 策略，批准副本目录、GitHub 仓库、branch 同步分支、读取凭据与可选 systemd 服务。

python3 scripts/code-sync.py agent-example --state data/native-admin
python3 scripts/code-sync.py agent-sha --state data/native-admin

默认 Agent 路径 /data/workspace/XDocker/scripts/code-sync-agent.py，策略 /data/workspace/XDocker/data/code-sync-agent/policy.json。使用 VPN / 内网 IP、固定身份引用及从可信渠道核对的 SSH 主机公钥。设备授权必须匹配来源分支；旧 v1 备份授权需更新并重新核对。

4. 计划与恢复

明确开启来源与计划后运行。GitHub SHA 回读确认后才分发；目标有修改、忽略文件碰撞、分叉或授权变化时停止。仅在副本实际更新后重启明确批准且定义固定的 systemd 服务，不代替构建或数据库迁移。

schema 1 升级至 schema 2 需要 SQLite 3.35+。升级前用旧版本 backup 备份；升级会保留历史，并关闭全部来源、计划和目标，等待重新核对。未知操作不自动重放，在执行记录中处理。归档保留回执与幂等记录。
