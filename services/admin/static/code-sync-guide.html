代码同步接入

日常配置在「研发协作 → 代码同步」。源码目录、SSH 身份和设备端目录须由各主机管理员预先授权。

1. 本机目录与 SSH 身份

在 XDocker 仓库根目录生成模板，保存到私有 0600 文件；填写 source_roots、允许引用的 identities，审核后开启 execution。

python3 scripts/code-sync.py policy-example --state data/native-admin
python3 scripts/code-sync.py policy-import --state data/native-admin --file /absolute/private/policy.json
python3 scripts/code-sync.py bootstrap-workspace --state data/native-admin

bootstrap 只读取主仓库并创建关闭状态的配置；默认每日 02:00、Asia/Shanghai。它不会提交或上传项目。页面上传目的分支限于 xdocker-backup/，源工作区和暂存区不变。

2. GitHub 凭据

在源码仓库分区点击「GitHub 凭据」，保存具有该仓库备份分支写权限的访问令牌，再在项目配置中选择它。令牌只保存在主机私有文件，不回显、不拼进 Git URL。

3. 目标设备

目前支持 Linux / macOS 目标设备（Windows Agent 尚未支持），需要 Python 3.9+、Git 和同一版本 XDocker Agent。将已发布的 XDocker 提交同步到设备；在该设备生成并审核私有 Agent 策略，批准每个副本的目录、GitHub 仓库、备份分支及可选服务。

python3 scripts/code-sync.py agent-sha --state data/native-admin
python3 scripts/code-sync.py agent-example --state data/native-admin

默认 Agent 路径 /data/workspace/XDocker/scripts/code-sync-agent.py，策略 /data/workspace/XDocker/data/code-sync-agent/policy.json；策略目录 0700，文件 0600。本机策略可调整这两个固定路径。私有仓库可在 Agent 策略中引用 secrets/ 下的 0600 GitHub 读取令牌。

页面添加设备时，填写 VPN 地址、用户、已授权的本机身份引用，以及从可信渠道核对的 SSH 主机公钥。不会自动接受陌生主机公钥。添加分发策略时，副本标识与目录必须匹配设备端策略。

4. 运行与结果

先预览文件，明确启用来源与计划。上传经 GitHub SHA 回读确认后才同步副本；工作区有修改、分支不一致、授权变化或无法快进时停止。更新后的 HEAD 必须是本次已确认 SHA。重启仅限 Agent 中明确批准并固定定义的 systemd 服务，且只在副本实际更新时执行。

中断或上传结果未知时，先在执行记录核对远端提交。结束跟进不代表操作成功。归档会保存私有回执文件，只移走已结束记录；未确认记录继续保留。代码副本同步不替代各项目自己的构建、镜像发布、数据迁移和部署验收。
