# XDocker 全实例备份计划

控制台左侧 **备份计划**（`/#backup-plans`）管理 XDocker 外层全实例维护备份。它复用[实例备份](backups.md)的 PostgreSQL 逻辑备份、Redis RDB、私有配置与运行文件打包，不修改 PowerX 的应用内数据库计划，也不使用 PowerX 管理员密码。

本功能本地实现完成后仍需按授权流程发布 Admin 镜像、同步相同仓库提交并部署，服务器才会出现新页面。**没有自动启用任何服务器计划。** 全局调度、每个实例计划和自动清理分别控制，默认均关闭。

## 默认与影响

| 字段 | 默认值 / 来源 | 含义 |
| --- | --- | --- |
| 实例 | `instances/<实例>/instance.json` 中登记并启用的 PowerX | 只处理这个实例的四个服务；未登记或取消登记的实例不调度 |
| 计划启用 | 关闭 | 保存禁用计划不会开始备份；首次启用安排严格未来的时间点 |
| 周期 / 时间 | 每天、03:00、上海时间 UTC+08:00 | 可改每天或每周指定星期；当前支持上海时间和 UTC |
| 最多迟到 | 5 分钟，范围 1–30 | 只限制允许开始的时间；超出后跳过，不在业务时段补跑 |
| 保留份数 | 7，范围 1–100 | 仅在自动清理开启时生效；自动清理关闭时不按份数删除 |
| 自动清理 | 关闭 | 成功创建并校验本次备份后，才尝试清理旧成功备份 |
| 服务器调度开关 | `ADMIN_BACKUP_SCHEDULER_ENABLED=false` | `services/admin/.env` 的显式运行开关；网页不能修改这个开关 |

开始备份会短暂停止所选实例原来运行的前端、后端，PostgreSQL/Redis 保持运行；完成或失败后尝试恢复原状态。**允许迟到不是完成时限**：备份、压缩及服务恢复可能持续超过允许开始范围。不能保证停机只持续几分钟；不要把这个值当作严格停机 SLA。

当前全局一次执行一个运行操作，计划备份与手动备份、恢复验证、证书等运行操作共用执行锁。多个实例应错开时间：若一直被其他操作占用，超过该实例允许开始时间便跳过并记录，不排队到白天执行。

## 保存与启用

1. 打开 **备份计划 → 编辑计划**，选择实例的周期、时间、时区、允许迟到和保留份数。下一计划时间按所选计划时区显示，最近任务时间按浏览器本地时间显示。
2. 默认先保存禁用计划。填写完整实例名并保存；成功信号为“计划禁用”，没有立即创建备份任务。
3. 确定维护时间后勾选 **启用此实例计划**，同时勾选 **确认允许暂停前后端**，输入完整实例名确认。若开启自动清理，另外勾选 **确认删除旧成功备份**。每次保存都重新确认；不会把上一次勾选当作新配置授权。
4. 保存成功后显示配置的下一时间。**全局调度关闭时，即使实例计划已启用，也不会自动备份**；页面会明确提示开关关闭。启用计划不会立即执行“补一份”。
5. 明确授权发布部署及维护范围后，才在服务器配置中开启全局开关：

   ```dotenv
   # services/admin/.env；默认保留 false
   ADMIN_BACKUP_SCHEDULER_ENABLED=true
   ```

   按本地配置、授权推送、服务器同步与 Admin 更新流程维护，不由代理直接在服务器改仓库代码。服务器私有 `.env` 的修改、Admin 重启及开始使用计划需符合明确授权范围。重启前确认没有备份或其他运行任务正在执行，避免中断服务恢复。

6. 页面应显示 **调度进程运行中**，实例应显示 **计划已启用**。到计划时间后，查看最近执行和 **操作记录**：备份状态“已校验”、任务“成功”，开启清理时还须核对清理结果。新计划约每 30 秒检查一次；开始前还会核对登记、配置版本和时间范围。

运行一个 Admin 实例、一个 Gunicorn worker（镜像默认配置）。进程级调度锁用于拒绝重复调度进程，不把多个控制台副本或手动绕过管理 API 的操作当作已支持的并发部署。

## 修改、禁用和异常

- **编辑冲突**：另一页面先保存时，当前版本被拒绝。重新读取计划，再按新数据编辑确认；不会自动重发旧配置。
- **禁用后续计划**：输入完整实例名确认。只停止后续调度；已经开始的备份和清理继续按开始时配置完成并恢复服务。编辑正在执行的计划也只影响后续运行。
- **错过时间**：记录跳过及原计划时间，安排下一个未来时间，不补跑积压。管理员确需补备份时，另行阅读维护影响，手动创建。
- **备份失败**：保留失败任务和备份清单，不自动重试、不自动清理旧备份。先看操作记录以及前后端实际运行状态，尤其是 `resume_failed`。
- **备份成功、清理失败**：任务显示失败，但备份阶段可能显示“已校验”。保留新备份并提示清理未完成；不把清理失败解释为没有备份。清理可能已删除部分旧成功备份，需按实际目录和清单核对。
- **重启未确认**：已有任务恢复机制先尝试恢复本控制台暂停的服务；计划元数据标记未确认。已消费的时间点不会因重启再执行一遍。尚未开始且仍在允许开始范围内的计划可以执行；过期计划只记录跳过。
- **计划文件异常**：显示错误，保留原文件，不覆盖成空计划、不启动无法解析的计划。通过授权的终端维护核对私有文件及任务记录。

Docker 运行状态读取失败而 Admin 计划 API 正常时，仍可管理计划元数据；这不会放开容器启停等运行操作。SSH 断开、浏览器离线或会话/操作验证失效时，先恢复连接并重新验证，不自动重发保存请求。

自动清理只删除超过保留份数的旧 `ready` 成功备份。清理前必须至少有一份**留在保留集合中且 SHA256 校验通过**的备份；没有有效保留备份时拒绝删除。失败、中断及服务恢复失败记录继续保留。本机制不代表备份已经通过数据库恢复演练，仍需另外进行隔离恢复验证和业务验收。

## 存储、备份与回退

```text
data/admin/backup-plans.json      计划、下一时间、最近执行/跳过（600）
data/admin/backup-plans.lock      配置更新锁
data/admin/backup-scheduler.lock  调度进程锁
data/admin/admin.sqlite3         复用既有任务及审计记录；没有新增业务数据库表
data/instance-backups/<实例>/<id>/  实际备份包与清单
```

计划只包含运行元数据，不保存数据库密码、PAT 或私钥。管理目录仍为私有目录；**实际备份包含业务数据和密钥**，继续按实例备份指南安全保管。计划按文件锁更新、原子写入并同步落盘；先消费时间点再进入业务操作，避免重启重复执行。

管理状态备份需在无运行任务时按 Admin 维护流程停止服务，完整备份 `data/admin/` 和实际备份目录。回退前先关闭计划/全局调度，在无活动任务时回退至已验证 Admin 镜像；保留计划和备份文件用于核对。此回退不恢复或覆盖业务数据库。

异地存储、备份加密、PITR、生产覆盖恢复均未在本任务实现；PowerX 应用内数据库计划继续由其自己的备份中心管理。不要让两个计划在同一时段执行。

## 本地验证与待验收

本地测试使用临时计划文件和模拟 Docker，覆盖未来时间计算、时区/每周、重复时间点、错过窗口、重启、不重试、执行锁、确认/CSRF、版本冲突、自动清理保留有效备份，以及计划页面事件。

尚未发布或部署此功能，也未执行真实服务器定时停机备份。真实容器、计划时间触发、服务恢复、浏览器操作和恢复演练仍需在授权环境分别验收。
