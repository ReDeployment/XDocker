# 部署前检查

在 XDocker 控制台左侧打开 **部署前检查**，地址为当前控制台地址的 `/#preflight`，例如 `http://127.0.0.1:19080/#preflight`。需要已有的管理登录会话。

该页面检查当前已启用的站点、已登记启用的 PowerX 实例和宿主机报告中的配置。它不会安装 Docker、拉取镜像、初始化数据库、启停服务、修改 DNS/权限或签发证书。更新本功能仍需按仓库规则完成授权发布和服务器同步；本地实现完成不代表服务器已有这个页面。

## 操作顺序

1. 在**服务器的 XDocker 仓库目录**，用实际部署用户生成宿主机报告：

   ```bash
   cd ~/workspace/XDocker
   sh scripts/preflight.sh --save
   ```

   默认只向终端输出检查结果；`--save` 额外保存固定文件 `data/events/deployment-host.json`，权限为 600，覆盖上一次诊断报告。它不改 `.env` 或业务数据。通常使用 `ubuntu` 执行；Docker socket 无权限时先按服务器安装指南处理。不要通过本脚本自动添加组或修改权限。

2. 打开检查页，点击 **重新读取清单**，再点击 **检查全部**。页面逐项显示进度；也可直接点击某行 **重新检查**。单个外网/DNS 检查最多运行 10 秒，超时后结束自己的子进程。
3. 核对每行的实际结果、处理建议和时间。结果分为 **通过、需核对、失败、未确认**；没有执行的项目和过期结果不计入通过。**停止后续检查**会在当前只读项目结束后退出，保留已经完成的结果。
4. 遇到失败，先按证据排查对应网络、配置或权限；重新生成宿主机报告后，再读取清单并重新检查。页面不会自动修复，也不会自动开始部署。

检查结果保留在当前 Admin 进程内，重启后重新检查。网页的常规状态轮询不会自动重新执行这些外网检查。超过 15 分钟的结果需要重新检查；宿主机报告还须来自同一个部署目录、同一个已登记部署提交。修改目标 IP、域名、镜像或重新生成报告后，相关旧结果也需要重新检查。

## 每项结果表示什么

| 检查 | 数据来源与成功信号 | 未覆盖范围 / 失败处理 |
| --- | --- | --- |
| Docker Engine | Admin 经 Unix socket 读取 Docker `/version`，返回版本和平台 | 不等于 Compose 配置或业务健康通过；API 不可用时检查页仍可打开 |
| Admin 数据文件系统 | 检查 `/state` 挂载所在文件系统的可用空间 | 不代表 DockerRootDir 所在磁盘；不足 1 GiB 或 10% 提示核对容量，不自动清理 |
| 配置读取与权限 | 当前 Admin 身份能读取检查范围内的私有 `.env`，组/其他用户无权限 | 不证明宿主机写入权限或 PostgreSQL/Redis 容器 UID 权限；不显示配置原文 |
| Docker 发布端口 | 按根 `.env` 的 HTTP/HTTPS 地址和端口，检查正在运行的容器发布信息 | 已有 XDocker Nginx 可继续拥有端口；其他容器占用失败；不停止占用方，不展示无关容器信息 |
| 宿主机 Compose | 报告中的 `docker compose version` 及共享入口、登记实例的 `config --quiet/--images` 成功 | 只做静态配置检查，不创建容器；错误原文可能含配置，因此不在报告回显，需在终端人工核对 |
| 宿主机磁盘 | 报告检查部署目录和 DockerRootDir 文件系统 | 镜像层、数据库增长和备份还需估算；DockerRootDir 未能检查时显示需核对 |
| 部署目录权限 | 报告记录执行身份 UID，检查部署目录、报告/备份目录及 `.env` 访问 | root 检查不证明 ubuntu 权限；缺失目录不自动创建（保存诊断报告目录除外） |
| 宿主机端口 | 对计划绑定的地址/端口临时 bind 后立即关闭，不 listen | 已有监听或无绑定权限时需结合 Docker 端口结果核对；不检查安全组、公网入站或关闭其他服务 |
| GHCR / Docker Hub | Admin 容器 GET 固定 `/v2/`，HTTP 200 或带 Registry V2 标识的 401 | **401 说明接口可达，不说明私有镜像认证成功**；也不证明 Docker daemon 的代理/DNS或镜像层下载正常 |
| 正式 / 测试 ACME | GET 固定 directory，HTTP 200 并含预期账户、订单和 nonce 地址 | 不发起订单、HTTP-01 或证书签发；还需公网 DNS 和 80 入站验证 |
| DNS | Admin 容器的系统解析返回 IPv4/IPv6 地址，与配置的预期地址核对 | 系统 DNS 不代替外部传播检查；未登记的 AAAA 也可能让请求走旧服务器 |
| 目标镜像 | 检查 Docker 本机缓存，并对 GHCR/Docker Hub 匿名读取清单元数据 | 不读取 `~/.docker/config.json`、PAT 或私钥；不拉镜像层，不保证平台可用或容器启动 |

宿主机报告通过现有只读 `/reports` 挂载展示，不给 Admin 增加宿主机命令执行器或更广的目录挂载。外网探测使用固定 registry、匿名 token、ACME 端点；不接受网页传入自定义 URL，不跟随重定向。其他 registry 仅显示匿名检查未实现，需要在服务器终端核对。

## 配置 DNS 预期地址

目标公网地址统一配置在根 `.env` 的 `PREFLIGHT_EXPECTED_IPS`，空格分隔计划使用的 IPv4/IPv6。公开 `.env.example` 默认留空，真实地址只填写在不提交 Git 的私有 `.env` 中；换服务器时修改私有配置并同步 DNS，初始化保留已有值。以下为文档示例地址：

```dotenv
PREFLIGHT_EXPECTED_IPS="192.0.2.10" # 仅为文档示例，替换为实际服务器地址
```

如正式使用 IPv6，再加入实际服务器 IPv6 地址。没有配置这个字段时，DNS 行展示解析结果和“未核对目标服务器 IP”；它不会根据浏览器本机地址或容器内网 IP 猜测公网地址。DNS 仍返回其他 A/AAAA 地址时检查失败。

按本地配置、授权推送及服务器同步流程维护该字段；网页不修改它，也不替你改 DNS。更新后重新读取清单并执行 DNS 项目。成功信号是“系统 DNS 返回地址与目标清单一致”，之后仍需外部访问和证书验证。

## 私有镜像如何验收

匿名读取被拒绝时，显示 **需核对**。私有包、权限不足、包名错误可能得到相似的拒绝响应，不能只凭匿名检查决定原因。该结果不意味着必须公开镜像。

在服务器使用实际部署上下文登录并验证已确认的目标镜像，例如此前使用 `sudo docker`，则认证也应在相同上下文：

```bash
# 登录步骤和 PAT 权限见 GHCR 指南；不要把 PAT 粘贴到网页或聊天中。
sudo docker pull ghcr.io/OWNER/IMAGE:CONFIRMED_TAG
```

这条命令会下载镜像，须由你决定执行；检查页不会自动运行。匿名清单读取成功也只说明元数据可读。完整拉取完成、平台正确、启动健康与 PowerX 首次 Setup 应分别验收。
