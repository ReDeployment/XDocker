# XDocker 管理能力任务清单

更新日期：2026-10-11。

本清单用于 PowerX 新版本准备期间推进 XDocker 自身的管理能力。执行顺序和授权边界遵守 [AGENT.md](../../AGENT.md)。P0–P3 已按用户指令完成本地实现与隔离验证。用户随后授权推进交付第 1 步：在独立任务分支提交、推送、建立 PR 并跟进双架构 CI；不合并 main、不发布镜像、不操作服务器。正式发布契约与目标服务器验收仍待完成。

## 已有能力与缺口

- 专属控制台：服务状态、日志、网站检查、证书检查与续期操作、FRP 入口、操作记录。

- 实例备份：手动创建、下载、校验、隔离数据库恢复验证、显式保留清理。
- 管理入口通过本机 SSH 隧道访问。本轮补充了 XDocker 托管的自动重连与网页连接状态；真实托管及部署仍待验收。
- 本轮补充部署前统一检查页、默认禁用的逐实例备份计划及只读镜像版本管理；真实容器、浏览器、发布契约接入及服务器验收待完成。

## XD-001：管理连接稳定性

### 问题与目标

此前管理页出现过 `Failed to fetch`，其中实际排查确认过本机 19080 没有监听，而服务器 Admin 正常、令牌仍有效。页面只显示底层 fetch 错误，容易被误认为令牌失效。现有保活 SSH 命令可以检测失联，但没有完整的客户端自动重连机制。

目标：本机连接可启动、查看、停止和自动恢复；网页准确区分连接失败、服务器错误、登录失效，不让网络恢复重复触发运行操作。

### 工作项

- [x] 提供 XDocker 自有隧道管理入口，明确本机端口、服务器端口和 SSH 主机别名；默认本机 `127.0.0.1:19080` 转发服务器 `127.0.0.1:9080`。
- [x] macOS 使用独立 LaunchAgent 托管隧道；Linux 等平台的支持范围单独说明，不把 macOS 实现当作通用实现。
- [x] 使用系统 SSH 认证、known_hosts 和保活检查。连接断开后间隔重试，避免无间隔循环；主机身份或认证错误给出明确诊断。
- [x] 提供 start/status/stop 操作，检查端口冲突；停止仅影响本工具管理的连接。
- [x] 控制台显示连接状态、最近成功读取时间和重新检查入口。
- [x] 错误分类：浏览器离线、接口不可达、服务端 5xx、登录 401、来源/CSRF 403。无响应时不判断为 token 错误，端口监听存在也不直接判断 API 健康。
- [x] 网络恢复后仅恢复只读状态刷新，不自动重发登录凭据、备份、启停、续期或其他变更请求；结果不明的变更先查操作记录。
- [x] 更新 [管理控制台指南](../guides/admin/README.md)，给出启动、成功信号、断线恢复、端口冲突和停止操作。

### 已涉及的 XDocker 文件

- 新增本地隧道入口 `scripts/admin-tunnel.sh`，与服务器端 `scripts/admin.sh` 分开。
- 新增 `scripts/admin_tunnel.py`，提供前台监督和 macOS LaunchAgent 托管，按仓库和端口识别自有任务。
- `services/admin/static/app.js`、`index.html`、`style.css`：状态呈现及错误分类。
- `tests/`：临时连接和前端状态逻辑检查；`docs/guides/admin/`：使用说明。

实现仅限 XDocker，不修改其他项目，也不覆盖用户的 `~/.ssh/config`、私钥、认证方式或已有隧道。

### 验收标准

1. 正常连接可访问 `/healthz`，已登录用户可读取管理 API。
2. 临时断开测试连接后能检测失联，并在网络恢复后重连；不得为测试擅自中断用户当前隧道或服务器服务。
3. 端口被其他进程占用时明确报错，不杀掉占用进程，不创建重复托管任务。
4. 未配置可信主机或认证不可用时，不关闭 SSH 主机验证、不自动接受未知主机。
5. 各类 HTTP/网络错误有对应提示；网络错误不显示“令牌不正确”。
6. 重连不重复执行变更请求；令牌不进入日志、URL、localStorage 或托管配置。
7. stop 只停止 XDocker 自有连接，FRPC、其他 SSH 会话及网站保持原状态。

- Python 隔离验证：系统 SSH 参数、严格主机验证、端口冲突、不覆盖重复托管配置、目录与文件权限、只操作自有任务、健康响应分类、模拟 SSH 子进程失败后重连及退出清理。

### 影响与回退

本地托管会新增一个用户级任务，控制台更新涉及 Admin 镜像。实施先在隔离端口验证；安装本机托管任务、发布镜像、服务器更新均须符合用户明确授权范围。回退时卸载本工具的托管任务，恢复手动 SSH 命令；管理镜像可回退到此前已验证版本。服务器入口持续绑定回环地址，不新增公网管理端口。

## XD-003：实例备份计划

范围：在现有手动备份机制上规划按实例的执行周期、维护窗口、保留份数及最近任务结果。全实例备份与 PowerX 应用内备份策略分别管理，避免重复调度。

验收：只处理明确登记的实例，支持禁用计划，防止同实例任务重叠；失败保留记录，清理至少保留一份有效备份。计划创建前明确暂停前后端的影响。调度、异地存储和加密分别定义范围，不把“备份完成”当作完整恢复成功，不自动覆盖业务数据库。

用户已选择“先实现计划管理，默认禁用；逐实例配置时间和保留份数”。本轮不启用真实服务器调度，不创建实际计划备份；未来每个计划仍需确认维护/删除影响，并按授权发布部署。
